# راه‌اندازی Firebase برای EchoChat

> **این مرحله برای اجرای نسخهٔ ابری ضروری است.** تا وقتی Firebase پیکربندی نشده باشد، برنامه به‌جای نمایش کاربران و گفتگوهای ساختگی، صفحهٔ راه‌اندازی را نشان می‌دهد.

## ۱. ساخت پروژه و ثبت برنامه

1. در [Firebase Console](https://console.firebase.google.com/) یک پروژه بسازید.
2. از مسیر Project settings، یک Android app با شناسهٔ دقیق زیر ثبت کنید:
   ```
   com.aistudio.echochat.vpkzqr
   ```
3. فایل `google-services.json` را دانلود کرده و در مسیر زیر قرار دهید:
   ```
   echochat-fixed-source/app/google-services.json
   ```
4. این فایل را در commit عمومی قرار ندهید؛ به‌خصوص اگر فایل تنظیمات شامل اطلاعات حساس محیط شماست. برای CI می‌توانید آن را با روش امنی خارج از Git نگه دارید و در مرحلهٔ build وارد کنید.

## ۲. فعال‌سازی روش‌های ورود

در Firebase Console به **Authentication → Sign-in method** بروید و این روش‌ها را فعال کنید:

- **Email/Password** برای ثبت‌نام، ورود و بازیابی رمز عبور.
- **Google** برای ورود با حساب Google.

برای ورود Google، Web client ID از منبع تولیدشده توسط Google Services Plugin خوانده می‌شود. نیازی به قرار دادن آن به‌صورت hard-code در فایل Kotlin نیست.

## ۳. ساخت دیتابیس و اعمال قوانین امنیتی

از **Build → Firestore Database** یک دیتابیس Cloud Firestore بسازید. سپس محتویات فایل `firestore.rules` در ریشهٔ مخزن را در بخش **Rules** کنسول قرار دهید و **Publish** کنید.

این قوانین اجازهٔ خواندن کانال‌های عمومی را فقط به کاربران واردشده می‌دهند و هنگام ایجاد پیام، تطبیق `senderId` با شناسهٔ حساب Firebase را بررسی می‌کنند. از باز کردن دسترسی عمومی با عباراتی مانند `allow read, write: if true` خودداری کنید.

## ۴. App Check

کلاس `EchoChatApplication` برای نسخهٔ Debug از Debug App Check Provider و برای نسخهٔ Release از Play Integrity استفاده می‌کند.

- برای توسعه، Debug token نمایش‌داده‌شده در Logcat را در Firebase Console ثبت کنید.
- قبل از فعال کردن enforcement، رفتار برنامه را با تنظیمات واقعی پروژه آزمایش کنید.
- انتشار Release باید با کلید امضای متعلق به مالک برنامه و Play Integrity پیکربندی‌شده انجام شود.

## ۵. بیلد و آزمون دستی

در Android Studio پروژهٔ `echochat-fixed-source` را باز کنید، Gradle Sync را اجرا کنید و سپس `assembleDebug` را اجرا کنید.

با دو حساب Firebase مستقل و روی دو دستگاه (یا یک دستگاه و یک شبیه‌ساز) آزمایش کنید:

1. با حساب اول ثبت‌نام کنید و پیام را در اتاق `general` بفرستید.
2. با حساب دوم وارد شوید و بررسی کنید پیام روی دستگاه دوم دریافت می‌شود.
3. پس از قطع و وصل اینترنت، بازیابی پیام‌ها را بررسی کنید.
4. با حساب دوم تلاش نکنید پیام حساب اول را ویرایش یا حذف کنید؛ قوانین سرور باید درخواست غیرمجاز را رد کنند.
5. ورود، خروج، بازیابی رمز، حالت آفلاین و خطاهای Firebase را آزمایش کنید.

## محدودهٔ فعلی و کارهای باقی‌مانده

این شاخه ورود ابری و همگام‌سازی زندهٔ پیام‌ها در **اتاق‌های عمومی** را فراهم می‌کند. دیتابیس Room همچنان کش آفلاین UI است.

موارد زیر هنوز برای انتشار عمومی کامل نشده‌اند و نباید به‌عنوان قابلیت سروری فعال تبلیغ شوند:

- پیام خصوصی واقعی بین دو حساب و مدیریت اعضای گفتگو.
- همگام‌سازی پست‌ها، دیدگاه‌ها، استوری‌ها و پروفایل با سرور.
- وضعیت تحویل/خوانده‌شدن، حضور آنلاین و نشانگر تایپ بین کاربران.
- حذف و ویرایش پیام با همگام‌سازی کامل تغییرات، بارگذاری فایل و اعلان Push.
- کنترل سوءاستفاده و اسپم، گزارش‌گیری خطا، سیاست حفظ حریم خصوصی، حذف/خروجی‌گرفتن داده‌ها و آزمون‌های یکپارچه با Firebase Emulator.

قبل از انتشار، قوانین و جریان‌های داده را در پروژهٔ Firebase خود آزمایش کنید. ساخت موفق APK به‌تنهایی تضمین‌کنندهٔ آمادگی برای انتشار نیست.
