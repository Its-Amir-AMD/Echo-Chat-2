# راه‌اندازی Firebase برای EchoChat

> **برای استفادهٔ ابری، Firebase واقعی لازم است.** تا وقتی Firebase پیکربندی نشده باشد، برنامه صفحهٔ راه‌اندازی را نشان می‌دهد و کاربران یا گفتگوهای ساختگی را به‌عنوان دادهٔ واقعی نمایش نمی‌دهد.

## ۱. ساخت پروژه و ثبت برنامه

1. در [Firebase Console](https://console.firebase.google.com/) یک پروژه بسازید.
2. از مسیر Project settings، یک Android app با شناسهٔ زیر ثبت کنید:
   ```
   com.aistudio.echochat.vpkzqr
   ```
3. فایل `google-services.json` را دانلود کرده و در مسیر زیر قرار دهید:
   ```
   echochat-fixed-source/app/google-services.json
   ```
4. این فایل را در commit عمومی قرار ندهید؛ برای CI از روش امنی برای تزریق فایل استفاده کنید.

## ۲. فعال‌سازی روش‌های ورود

در **Authentication → Sign-in method** این روش‌ها را فعال کنید:

- **Email/Password** برای ثبت‌نام، ورود و بازیابی رمز عبور.
- **Google** برای ورود با حساب Google.

ثبت‌نام با ایمیل یک نام کاربری یکتا (۳ تا ۲۴ حرف انگلیسی، عدد یا زیرخط) می‌گیرد. کاربر حساب‌های دیگر را با همین نام کاربری پیدا می‌کند؛ ایمیل در فهرست عمومی کاربران منتشر نمی‌شود. حساب‌های Google در صورت نداشتن نام کاربری، یک handle پیش‌فرض دریافت می‌کنند.

## ۳. ساخت دیتابیس و اعمال قوانین امنیتی

از **Build → Firestore Database** یک Cloud Firestore بسازید. سپس محتویات `firestore.rules` در ریشهٔ مخزن را در بخش Rules قرار دهید و **Publish** کنید.

این قوانین دسترسی به اتاق‌های عمومی را فقط به کاربران واردشده می‌دهند، هنگام ایجاد پیام شناسهٔ فرستنده را با Firebase UID تطبیق می‌دهند، فهرست عمومی نام‌های کاربری را غیرقابل‌فهرست‌گیری نگه می‌دارند و خواندن پیام خصوصی را فقط به دو عضو همان گفتگو محدود می‌کنند. از باز کردن دسترسی عمومی با عباراتی مانند `allow read, write: if true` خودداری کنید.

## ۴. App Check

کلاس `EchoChatApplication` برای Debug از Debug App Check Provider و برای Release از Play Integrity استفاده می‌کند.

- برای توسعه، Debug token نمایش‌داده‌شده در Logcat را در Firebase Console ثبت کنید.
- قبل از فعال کردن enforcement، برنامه را با تنظیمات واقعی پروژه آزمایش کنید.
- برای انتشار Release، کلید امضای مالک برنامه و Play Integrity را درست پیکربندی کنید.

## ۵. بیلد و آزمون دستی

در Android Studio پوشهٔ `echochat-fixed-source` را باز کنید، Gradle Sync را اجرا کنید و `testDebugUnitTest`، `lintDebug` و `assembleDebug` را اجرا کنید.

با دو حساب Firebase مستقل روی دو دستگاه یا یک دستگاه و یک شبیه‌ساز این سناریوها را آزمایش کنید:

1. با حساب اول ثبت‌نام کنید، نام کاربری‌اش را از بخش پروفایل ببینید و در اتاق `general` پیام ارسال کنید.
2. با حساب دوم وارد شوید و تأیید کنید پیام اتاق عمومی دریافت می‌شود.
3. از حساب دوم با نام کاربری حساب اول یک گفتگوی خصوصی بسازید و در هر دو سمت پیام ارسال و دریافت کنید.
4. اطمینان پیدا کنید گفتگوی خصوصی برای حساب سوم قابل خواندن نیست و یک حساب نمی‌تواند پیام حساب دیگر را حذف یا ویرایش کند.
5. پس از قطع و وصل اینترنت، بازیابی پیام‌ها را بررسی کنید.
6. خروج، تغییر حساب، بازیابی رمز، ثبت‌نام با نام کاربری تکراری و خطاهای Firebase را آزمایش کنید.

## محدودهٔ فعلی و موارد باقی‌مانده

ورود ابری، همگام‌سازی زندهٔ پیام‌های اتاق‌های عمومی و گفتگوهای خصوصیِ دو عضوی در این شاخه پیاده‌سازی شده‌اند، اما تا زمان آزمون با پروژهٔ Firebase شما، رفتار عملی و قوانین را نباید تأییدشده فرض کرد. Room کش محلی برنامه است و هنگام جابه‌جایی به حساب متفاوت، داده‌های خصوصی و اجتماعی محلی پاک می‌شوند تا بین حساب‌ها نشت نکنند.

این موارد همچنان برای انتشار عمومی کامل نشده‌اند:

- همگام‌سازی پست‌ها، دیدگاه‌ها، استوری‌ها و تغییرات پروفایل با سرور.
- رسید واقعی تحویل/خوانده‌شدن، حضور آنلاین و نشانگر تایپ بین کاربران.
- ویرایش/حذف کامل و همگام‌سازی واکنش‌ها، بارگذاری فایل/تصویر و اعلان Push.
- کنترل سوءاستفاده و اسپم، سیاست حفظ حریم خصوصی، خروجی/حذف حساب و داده‌ها، و آزمون‌های خودکار با Firebase Emulator.
- رمزنگاری سرتاسری (End-to-end encryption).

قبل از انتشار، قوانین و جریان‌های داده را در Firebase خود بررسی و با دو حساب مستقل آزمایش کنید. ساخت موفق APK به‌تنهایی آمادگی انتشار را ثابت نمی‌کند.
